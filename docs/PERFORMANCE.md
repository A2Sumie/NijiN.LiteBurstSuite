# 默认流水线性能回归

日期：2026-11-14。平台：Apple M1 Max，Metal，6 CPU threads。

## 固定对照

输入顺序为 A9 III `DSC00889.ARW / DSC00894.ARW / DSC00895.ARW / DSC00897.ARW`。
统一参数：

```sh
nijinLBS --backend gpu --threads 6 --policy force-all \
  --anchor-frame first --no-sort-time --dither off \
  --out-raw result.dng --out-rgb result.tif INPUTS...
```

| 构建 | 端到端耗时 |
|---|---:|
| LiteBurstScaler 1.6.4 | 9.3808 s |
| Suite 2.0.0 发布版 | 112.3215 s |
| IBP 索引优化首轮 | 32.8196 s |
| IBP 索引 + 统计预扫描 ROI（当前本地构建） | **32.3152 s** |

默认功能保持启用，输出为 12024×8040 RGGB DNG 和 RGB TIFF。

## 预算失准原因

1. **IBP 源搜索放大**：每个 64×64 输出瓦片都使用整幅光流极值扩展源搜索框，且极值初始包含零。大漂移使大量无贡献源像素被反复逆映射。
2. **GPU halo 重叠**：DCT 金字塔、色差滤波、RL 与配准共同扩大 ROI；该组使用 35 个输出瓦片，每块同时处理邻域。原预算把单次局部算子成本当作完整调度成本。
3. **默认 CPU 阶段增加**：曝光匹配、传感器残差校准、方向权重、回投、色线细化均进入默认流程。五帧以上另含半栈重建及收缩，按独立阶段记录。

原“同速”和固定百分比预算由上述实测替代。首轮优化后的 GPU Stage4/5 仍为约 17 s，是下一项主要成本；采样 profile 的主要停留点是 GPU DCT 命令完成等待。

当前构建比发布版耗时减少 **71.2%**，耗时为旧版的 **3.44 倍**。正式重建共处理 **110,276,800** 个 1× ROI 像素，约为原片 **24,168,240** 像素的 **4.56 倍**；统计遍缩小为 **40,893,920** 像素。下一步重点是分离各滤波阶段的依赖域，减少重叠区域重复 DCT。

## 本轮实现

- 小流跨度采用紧边界；大流跨度建立 16×16 源块到目标瓦片的 CSR 索引。
- 遍历保持帧、源行、源列顺序；五步逆流遇到精确不动点时提前结束。
- 前向残差诊断按行并行，图像更新继续使用原四颜色调度。
- GPU 全局统计预扫描使用融合支撑域，正式重建沿用完整滤波 halo。
- 日志包含 C1/C2/C6 耗时、候选扫描数、索引内存，以及两遍 GPU ROI 像素总数。

首轮 IBP 为 **3.596 s**，扫描 **63,617,295** 个候选，CSR 索引 **1.01 MiB**。

## 精度与回归

独立全源扫描参考覆盖两轮更新、零/常量/大幅变流、稀疏 mask、边缘、饱和、NaN 与整体出界流。串并行输出一致。

O3 编译器对不同循环形状选择不同的融合乘加，旧/新 IBP 最大 float 差为 `2.38419e-7`；关闭浮点 contraction 后逐位一致，逆流坐标始终逐位一致。首轮全幅读回：DNG 857 个值相差 1 DN，TIFF 28,975 个值相差 1 DN，TIFF PSNR **136.33 dB**。

最终 ROI 优化构建与首轮像素结果一致；相对发布基线的 DNG/TIFF PSNR 分别为 **146.85 / 136.33 dB**。ASan/UBSan 的 Bayer/X-Trans CLI 工作流、独立全扫描参考、GPU 平场/接缝/超预算回退均通过。Windows 原生核心测试与八帧默认 Photo 的 CPU/Vulkan 对照通过，后者为 **105.35 dB**。

测试入口：`tests/test_suite_core.cpp`、`tests/test_suite_gpu.cpp`、`tests/test_suite_cli.py`。性能数据来自真实 CLI；质量对照使用 LibRaw/rawpy 与 tifffile 独立解码。
